# astryx-motion: integration guide for the core runtime

This crate has no Astryx dependencies, so `astryx-core` can depend on it.
Nothing here changes `astryx-core`; this guide shows how the runtime would
use it.

## 1. Tokens

```rust
use astryx_motion::tokens::{self, MotionTokens};
let motion: &MotionTokens = MotionTokens::by_name(theme.name).unwrap_or(tokens::DEFAULT);
```

`tokens/motion.json` is generated by `tools/export-motion-tokens.py` from
Astryx core's sources (see the script header) and turned into Rust by this
crate's `build.rs`, like `astryx-tokens` does for `themes.json`. Regenerate:

```sh
python3 tools/export-motion-tokens.py <astryx-repo> > tokens/motion.json
```

## 2. The clock

The runtime already receives `FrameInfo::dt` (seconds) every frame. Keep one
motion clock beside the existing `time`:

```rust
// in Runtime
motion_ms: f64, // monotonic, for gestures; never paused

fn frame(&mut self, frame: &FrameInfo, ..) {
    self.motion_ms += frame.dt as f64 * 1000.0;
    let mut moving = false;
    for a in self.animations_mut() { moving |= a.tick(frame.dt); }   // Animated, Presence, PressHighlight
    for r in self.repeats.poll(self.motion_ms) { self.handle_input(r, InputPhase::Pressed) }
    for e in self.press.tick(self.motion_ms) { /* PressEvent::LongPress */ }
    self.animating = moving;
}

fn wants_frames(&self) -> bool {
    self.animating                      // any Animated / Presence still moving
        || self.press.wants_frames()    // a held A may become a long press
        || self.repeats.wants_frames()  // a held direction repeats
        || self.stale || self.repaint
}
```

`dt` of the first frame after idle is 0 (shells already do this), so an
animation never jumps when frames resume.

The existing spinner clock (`time`, paused under reduced motion) stays as it
is: busy loops are outside `design:reduced-motion` and do not follow `tempo`
(`spec:AST-108` FR4).

## 3. Input to gestures

Map the contract's `Input` and `InputPhase` once, in the runtime:

```rust
use astryx_motion::gesture::{Phase, PressGesture, RepeatGesture, PagingGesture, Page, DPAD_REPEAT};

let phase = match input_phase { InputPhase::Pressed => Phase::Pressed, InputPhase::Released => Phase::Released };
match input {
    Input::Up | Input::Down | Input::Left | Input::Right => {
        if let Some(dir) = self.repeats.input(input, phase, self.motion_ms) { self.move_focus(dir) }
    }
    Input::A => for e in self.press.input(phase, self.motion_ms) {
        self.highlight.apply(e, motion, &self.policy, false);
        match e { PressEvent::Activate => self.activate_focused(), PressEvent::LongPress => self.context_request(), _ => {} }
    },
    Input::L2 | Input::R2 => {
        let page = if input == Input::L2 { Page::Previous } else { Page::Next };
        if let Some(p) = self.paging.input(page, phase, self.motion_ms) { self.page(p) }
    }
    _ => {}
}
```

Call `press.cancel()` and `repeats.cancel()` when focus moves by any other
path or the focused element goes away.

Shells deliver key repeats as extra `Pressed` events today. `RepeatGesture`
ignores a repeat of the input it already holds and runs its own clock, so a
shell's repeat and this one never double up.

## 4. Declaring a transition

A component keeps an `Animated<T>` in its state and asks for a target when
its props change. Pick the duration and curve from the theme's tokens, the
way the TypeScript component does, and let the policy decide what reduced
motion does with it:

```rust
use astryx_motion::{Animated, Motion, reduced::Change};

// Switch thumb: a state change on the theme's curve tokens.
let motion = Motion::curve(tokens.durations.fast, tokens.ease_move);
let motion = policy.travel(Change::Transition, motion, tokens);
self.thumb_x.animate_to(if on { 1.0 } else { 0.0 }, motion);

// A color-only change of state: instant under reduced motion on any pointer.
let motion = policy.travel(Change::Color, Motion::curve(tokens.durations.fast, tokens.ease_standard), tokens);

// A spring role (gesture components and the animator, spec:AST-107 FR3).
let spring = tokens.spring(tokens::springs::STATE_CHANGE).spring();
self.offset.animate_to(target, Motion::Spring(spring));
```

A surface that enters and leaves (Dialog, Popover, Tooltip, menus) uses
`Presence` (`spec:AST-090`):

```rust
self.presence.open(tokens.durations.medium, Interaction::Tap, tokens, &policy);
// paint with presence.opacity() and presence.travel() (0 = closed position)
for e in self.presence.close(Interaction::Tap, tokens, &policy) {
    match e { PresenceEvent::ReturnFocus => self.restore_focus(), PresenceEvent::Hidden => self.drop_popup() }
}
// while presence.is_leaving(): keep drawing the old content, route no input
// into it (accepts_input() is false), and leave a layer out of the a11y tree.
```

Paint never reads the clock directly: it reads `Animated::value()`, so the
display list stays a pure function of state.

## 5. Preferences

`Preferences::reduced_motion` maps to `MotionPolicy::prefers_reduced_motion`.
The policy also needs the primary pointer (`Pointer::Coarse` on a touch
screen) to choose between a cross-fade (DR2) and an instant change (DR3).
`Preferences` has no pointer field yet; see the contract proposal in the
lane report. Until it lands, use `Pointer::Fine`: every current shell
(desktop, web with a mouse, handhelds) is focus-first, and DR3 applies.
